## 2. 경제 기준선: 현재 실제 데이터
`data/web_catalog.json`은 기존 웹 원본 커밋 `7484ccd`에서 추출된 데이터다. **기존 자원 키**: iron, coal, mana, crystal, rareMetal, relic, cosmicShard, plasma. 이는 최종 청사진의 29광물과 1:1 대응하지 않는다. **기존 지역/해금 이름**에 '고대 유적', '우주 정거장'이 등장하지만, 이것이 최종 지상 8번째 지역의 승인 근거는 아니다.

**기존 레시피 원가 계산에 필요한 대표값(기존 데이터):**

| 제품 | 투입 | 판매가 | 제작 기본 시간 |
|---|---|---:|---:|
| 강철 steel | iron 2, coal 1 | 5G | 0초 |
| 석탄 벽돌 coalBrick | coal 3 | 4G | 0초 |
| 합금 alloy | steel 2, mana 1 | 20G | 0초 |
| 결정 합금 crystalAlloy | steel 2, crystal 1 | 22G | 3초 |
| 특수 합금 specialAlloy | alloy 3, coal 3 | 90G | 4초 |
| 정밀 부품 precisionPart | alloy 2, rareMetal 1 | 80G | 6초 |
| 철제 공구 ironTool | iron 4, coalBrick 1 | 14G | 2초 |
| 마력 램프 manaLamp | coalBrick 2, mana 2 | 30G | 3초 |

이 값은 **현행 구형 레시피 데이터**이고 신규 광물 v0.8 가격표를 넣어 계산한 순이익이 아니다. 원광 판매가격과 수급속도·재료 기회비용을 포함하지 않으면 이익률 판단 불가.

**기존 확장·자동화 수치:** 공방 건설비 `ceil(500×1.6^기존 공방 수)`, 기본 공방 상한 6(연구 후 8), 공방 업그레이드 기본 1500G·성장률 1.7; 일꾼 채굴 능력 첫 3회 업그레이드 비용 200/270/365G, 인부 수 상한 `8 + 4×(기지 레벨−1)`; 기존 자동 판매 해금 비용 배수 20. **신규 29광물 가격과 동시 변경 금지.**

**계산·검증 순서:**
1. 기존 `data/web_catalog.json`에서 제품별 재료·판매가·시간, 시설 비용·자동화 계수·직원 생산량을 기준선으로 고정.
2. 29종 광물의 신규 안정 ID, 지역, 등급, 기존 저장의 구형 자원과의 관계를 **별도 매핑 표**로 정의. 이름이 유사하다는 이유만으로 `mana`를 마정석으로 자동 치환하지 않는다.
3. 확정 v0.8 가격을 기준 시나리오로 두고 v0.9는 비교 시나리오로만 사용.
4. `시간당 순이익=(판매 수익−재료 기회비용−운영비)/(이동+채굴+제작+대기 시간)`으로 수동 채굴·가공·직원·자동 판매 비교. 분모는 같은 시간 단위로 맞춘다.
5. 기존 저장·광맥·제작소 레시피 키·연구 해금·자동화 대상이 모두 유지되는지 마이그레이션 회귀 검증.

## 3. 월드·탐험 작업
- **목표:** 지상 7개 지역, 지하 B1~B4, 거점 거리 링 희귀도, 지역 고유 광물, 사원·유물 사건. **현행:** 산맥 터널을 경계로 open/beyond와 4개의 beyond 세부 구역.
- **결정:** 현행 지역을 즉시 7개로 이름만 변경하지 않는다. 기존 월드 좌표·광맥 ID·플레이어 위치·터널 공사 진행과 연구·비용 상태를 유지하는 단계별 월드 확장 설계를 먼저 작성한다.
- **후속 명세:** 지역별 입구·경계·자원·해금·교통·스토리 트리거; 기존 저장의 좌표 충돌, 광맥 중복, 미도달 자원 및 접근 가능성 테스트.

## 4. 마을·생활 작업
- **이미 존재:** 감정소/박물관 `FACILITIES`, `stage`, `unidentified`, `appraised`, `owned`, `codex`, `donated`, `specimens`, `sites`, `district`, `decor` 저장과 연구 할인 계산.
- **우선 확장:** 기존 복구·기증·장식 시스템의 사용성·보상·건물 배치 검토. 기존 저장에서 누락된 필드가 정상 초기화되는지 확인.
- **이후 추가:** NPC 친밀도·일과·농사·계절 힐링 맵. 아직 확정하지 않은 0~100 친밀도와 5단계 마을 성장을 코드에 박지 않는다. 새로운 보상은 기존 연구 할인과 중복 적용·무한 지급을 검사한다.

## 5. UI·접근성 작업
- **현행 탭:** 가방·채굴·제작·판매·인부·연구·납품·마을·저장(9개).
- **보존할 개선:** 탭 내 컨트롤 재사용, 입력 중 갱신 방지, 스와이프 8px 판별, 납품 입력값 최신화, 가져오기 후 저장 초안 표시 및 재확인.
- **알려진 위험(`docs/qa/hud-input.md`):** 모바일 터치 대상 28~32 CSS px로 44px 권장보다 작음(문서 측정 당시 86개); 실제 Android/iOS 미검증; 창 포커스 변경 중 누름 상태 잔류 가능.
- **권고:** 작은 화면에서 모든 버튼을 일괄 44px로 만들면 오히려 화면이 가려질 수 있으므로 **중요 행동 버튼부터 최소 터치 영역을 확보**하고 메뉴 스크롤·화면 높이·가상 키보드 동작을 함께 검증한다. 실제 기기 검증과 Chromium 에뮬레이션은 별도 기록.

## 6. 사원·스토리 작업
- **현행:** `temple.gd`는 백미러·돌기둥 결말을 `endings` 배열에 누적하고, 두 회로를 켜야 결말을 기록한다.
- **목표:** 회차·월드 시드에 따라 **실제 발생한 A/B 사건**을 고정하고, 사원 재입장·기억 재구성으로 **두 경로를 체험**하는 것은 별도로 저장한다.
- **권고 데이터 분리(미승인):** `historical_event`(A/B 고정), `replay_endings_seen`(mirror/pillar 경험), `treatment_progress`(과학자 구출·치료)로 분리. 구형 `endings` 배열을 삭제하거나 다른 의미로 덮어쓰지 않는다. 구형 저장의 실제 A/B 역사를 알 수 없으면 임의로 과거 사건을 소급 확정하지 않는 마이그레이션 정책이 필요하다.
